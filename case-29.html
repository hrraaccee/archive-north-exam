Очередь выдачи

Внутренний сервис готовит архив документа к выдаче. Пока заявка лежит в очереди, документ можно отредактировать. Согласие рецензента относится к конкретному документу и его редакции. Система может хранить сколько угодно старых согласий.

29номер дела

Предмет проверки

Правило сервисаВыдать байты можно, только если именно редакцию, из которой взяты эти байты, одобрили как минимум два разных действующих рецензента. Автор документа не считается рецензентом для своего документа.

Договорённости о данных

ticket.document и requested_revision фиксируются при создании заявки и не меняются. Содержимое blob неизменно, blob.revision совпадает с ключом в db.blobs. При правке создаётся новая редакция и обновляется current_revision. Согласия не переносятся между редакциями. db — согласованный снимок, внутри одного вызова состояние не меняется.

01 │ def select_blob(ticket, db):
02 │     document = db.documents.get(ticket.document)
03 │     if document is None or document.archived:
04 │         return None
05 │     return db.blobs.get((document.id, document.current_revision))

votes.py

01 │ def reviewers(document, revision, db):
02 │     owner = db.documents[document].owner
03 │     result = set()
04 │     for vote in db.votes:
05 │         if (vote.document, vote.revision) != (document, revision):
06 │             continue
07 │         if vote.person != owner and vote.person in db.active_reviewers:
08 │             result.add(vote.person)
09 │     return result

Формат ответа

Укажи номер дела и один вывод: «нарушение», «правило соблюдено» или «недостаточно данных». Вывод касается только сформулированного правила.

  1. Назови файлы, функции и строки, на которых основан вывод.
  2. Проследи путь данных от входа до результата. Объясни, какое изменение состояния имеет значение.
  3. Если данных не хватает, назови недостающий контракт и объясни, как два допустимых варианта меняют вывод.
